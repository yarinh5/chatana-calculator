# Product and Architecture Decisions

| מזהה | החלטה | נימוק / השלכה |
| --- | --- | --- |
| D-01 | `guests` היא קבוצת הזמנה; `group_size` מקור אמת לכמות; `guest_members` פירוט אופציונלי | תואם ADR 001 ונתונים קיימים |
| D-02 | שימוש במודל `subscriptions` הקיים, ללא מסלולים או מחירים חדשים | Trial 21 יום, 5 הוצאות, payments/attendance Premium, פקיעה Read Only |
| D-03 | פיתוח Goal בענף מבודד; אין merge ל־main או פריסת Production לפני אינטגרציה מחוברת | הפיצ'רים החדשים תלויים ב־DB/ספקים שטרם אומתו |
| D-04 | אנשי קשר עוברים עיבוד מקומי; רק מי שהמשתמש בחר מוזמן נשלח לשמירה | פרטיות ומניעת יבוא אוטומטי של ספר טלפונים |
| D-05 | החלטה להזמין אינה RSVP; סטטוס מסירת WhatsApp אינו RSVP | שלושה מחזורי חיים עסקיים נפרדים |
| D-06 | מקור WhatsApp יוכל להיות מספר מרכזי או מספר עסקי של הזוג | בחירת המשתמש; מימוש אחרי ספק/מודל מסחרי מאושרים |
| D-07 | אין לייצר success ללא אישור כתיבה ממשי | חוזה mutation מחזיר הצלחה רק כששורה השתנתה בפועל |

החלטות על schema, ספק, עלות, הרשאות חדשות ומודל מסחרי יתווספו רק לאחר ראיות ואישור מתאים.
